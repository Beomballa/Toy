# NOREN Storefront Design Manifesto

## 1. 문제와 목적

현재 고객 화면은 탐색, 개인 관리, 재고 분석 기능이 한 화면에서 같은 우선순위를 가져 핵심 행동이 흐려지고, 화면마다 컨테이너와 버튼 규격이 달라 작은 폭에서 정렬이 무너진다. 이 문서는 Figma 없이도 코드와 문서가 같은 기준을 공유하도록 만드는 저장소 내 디자인 원본이다.

## 2. 사용자와 핵심 시나리오

- 처음 방문한 사용자는 홈에서 추천 주제를 이해하고 독립된 상품 목록으로 이동한다.
- 탐색 사용자는 상품 목록에서 검색, 정렬, 필터를 조합하고 상세로 이동한다.
- 구매 의향 사용자는 상세에서 상품 정보, 옵션, 수량, 주문 행동을 순서대로 확인한다.
- 재방문 사용자는 MY에서 주문, 후기, 관심 및 최근 활동을 이어간다.
- 비회원은 로그인과 회원가입 중 하나의 작업에 집중한다.

## 3. 제품 원칙

1. 한 화면은 하나의 핵심 목적을 가진다.
2. 분석 지표보다 상품과 다음 행동을 먼저 보여준다.
3. 상시 노출 행동은 주요 행동 1개와 보조 행동 2개 이내로 제한한다.
4. 고정 요소는 헤더, 모바일 구매 바처럼 문맥 유지가 필요한 경우에만 사용한다.
5. 모바일은 데스크톱 축소판이 아니라 읽기와 터치 순서에 맞게 재배치한다.
6. KREAM 등 레퍼런스의 정보 구조만 참고하고 상표, 문구, 자산은 복제하지 않는다.

## 4. 정보 구조

- 홈: 프로모션, 카테고리, 신규/추천/빠른배송 레일, 콘텐츠 진입점
- 상품 탐색: 검색, 필터, 정렬, 결과, 페이지 이동
- 상품 상세: 이미지, 가격, 상태, 옵션, 구매, 설명, 후기, 연관 상품
- MY: 주문, 후기, 관심, 최근 본 상품, 비교와 숨김 상태
- 인증: 로그인 또는 회원가입

홈의 추천, 랭킹, 빠른배송은 페이지 내부 앵커가 아니라 독립 컬렉션 URL로 이동한다. 전체 카탈로그의 관리 도구와 개인 데이터 분석은 홈의 기본 흐름에서 제외한다.

## 5. 상태와 예외

모든 데이터 영역은 로딩, 결과, 빈 결과, 오류와 재시도 상태를 가져야 한다. 모달과 드로어는 초점 이동, Escape 닫기, 배경 스크롤 잠금과 닫힌 뒤 초점 복귀를 보장한다. 품절 옵션과 실패한 주문 행동은 비활성 이유를 텍스트로 제공한다.

## 6. 성공 기준

- 360px 이상 화면에서 본문 가로 스크롤이 발생하지 않는다.
- 검색, 상품 상세 이동, 옵션 선택, 로그인/회원가입을 키보드만으로 완료할 수 있다.
- 상품 레일 헤더와 제어 버튼이 320px 폭에서도 겹치거나 잘리지 않는다.
- 홈 하단에서 검색 도구가 뷰포트에 따라오지 않는다.
- 공통 색상, 간격, 컨트롤 높이는 `design-tokens.css`를 사용한다.

## 7. 우선순위와 위험

1. 토큰과 공통 셸
2. 홈과 상품 탐색
3. 상품 상세 구매 흐름
4. MY와 인증
5. 접근성 및 시각 회귀 검증

기존 Vanilla JavaScript의 DOM 계약은 유지한다. 구조 변경이 필요한 경우 같은 작업 단위에서 이벤트와 리소스 테스트를 함께 수정한다.
